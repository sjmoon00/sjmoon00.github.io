Hugo 원본과 공개 산출물 저장소 분리하기

비공개 원본 저장소에서 Hugo를 빌드하고 공개 저장소에는 결과물만 배포하는 구조를 정리합니다.

개인 기술 블로그에는 공개 글뿐 아니라 작성 중인 메모와 초안도 함께 쌓인다. 원본 저장소와 호스팅 저장소를 분리하면 Markdown 원문은 비공개로 유지하면서, 브라우저가 사용하는 정적 파일만 공개할 수 있다.

저장소 역할 나누기#

두 저장소의 책임을 먼저 고정한다.

저장소공개 여부포함하는 내용
blog-sourcePrivateHugo 설정, Markdown, 초안, CMS 설정, 워크플로
sjmoon00.github.ioPublicHTML, CSS, JavaScript, 공개 이미지, sitemap

Public 저장소는 직접 편집하지 않는다. 항상 Hugo 빌드 결과로 전체를 동기화한다.

프로덕션 빌드 규칙#

프로덕션 빌드에서는 초안과 미래 날짜 글을 포함하는 옵션을 사용하지 않는다.

hugo \
  --gc \
  --minify \
  --baseURL "https://sjmoon00.github.io/"

빌드가 끝난 뒤에는 산출물 경계를 검사한다.

if find public -type f \( -name '*.md' -o -name '.pages.yml' \) | grep -q .; then
  echo "source file leaked into public output" >&2
  exit 1
fi

이미지가 초안보다 먼저 공개되지 않게 하기#

static/ 아래 파일은 Hugo가 그대로 복사한다. 초안에서만 사용하는 이미지도 static/에 두면 URL을 추측해 접근할 수 있다.

이 블로그는 CMS 업로드 이미지를 assets/images/에 저장한다. Markdown 이미지 렌더 훅이 실제로 참조한 리소스만 빌드 결과에 발행하므로, 공개 글에서 사용하지 않는 초안 이미지는 산출물에 포함되지 않는다.

배포를 원자적으로 유지하기#

배포는 다음 순서를 지킨다.

  1. Hugo 프로덕션 빌드
  2. HTML과 필수 파일 존재 확인
  3. 원본 파일 및 초안 전용 자산 누출 검사
  4. 공개 저장소를 임시 디렉터리에 clone
  5. rsync --delete로 결과 전체 동기화
  6. 변경이 있을 때만 commit과 push

빌드나 검사 단계가 실패하면 공개 저장소에는 어떤 변경도 push하지 않는다. 이미 정상 배포된 사이트는 그대로 유지된다.

마무리#

이 구조의 핵심은 공개 저장소를 소스 저장소처럼 사용하지 않는 것이다. 공개 저장소는 언제든 다시 만들 수 있는 빌드 산출물이고, 글과 설정의 기준은 Private 저장소 하나뿐이다.
